## Information architecture

Home routes readers to a sequential Learning Course, Educator's Guide,
Design Handbook, Mechanism Examples, Best Practices, Other Resources,
and Contribution. A separate Website Feature Guide explains interface conventions.

The course teaches Onshape through FRC work. The handbook supplies deeper
explanations for lookup; it is not another required lesson sequence.
Mechanism examples are curated explanations of particular designs.
Resources supply tools such as FRCDesignLib, FeatureScripts, KrayonCAD,
glossary, and design challenges.

This distinction between learning a skill and looking something up is directly
useful for Chiron's course/hardware/API goals.

## Pedagogy and review

The course builds competence through repeated FRC-relevant work rather than a
broad catalog of CAD commands. Early projects are closely guided; later projects
retain only essential steps. Students repeatedly apply organization and design
intent as well as geometric skills.

The educator guide favors self-paced work with individualized support, light
prerequisites, and repeated practice. Its design style emphasizes plates and
patterned tubing to lower fabrication barriers while preserving capability.
These are stated rationales, not a measured comparison of all teaching methods.
[Educator introduction](https://frcdesign.org/educators-guide/introduction/)

[Focusing on Improvement](https://frcdesign.org/learning-course/stage1/1a/focusing-on-improvement/)
adds an explicit learning loop: complete work, pause, self-check without the
solution, compare with reference work, reflect on difficulties, and choose what
to practice next. Mentor review supplements rather than replaces self-review.
Chiron can translate this into prediction, execution, debugging, comparison,
and explanation of code.

Stage 2's recurring concept → layout → implementation → summary structure
creates familiarity while the mechanism changes. Some summaries include
feedback links, creating a route for improving confusing teaching material.

## Visual and authoring choices

Observed course layout: green branding, dark reading surface, strong headings,
section-specific left navigation with active-page highlighting, nested groups,
callouts, and illustrated section introductions. Source includes Inter styling,
a green `#43A047` accent, responsive rules, and custom sidebar/TOC components.
The authoring feature set includes image enlargement/lightboxes, captioned
slideshows, prominent CAD-document links, glossary tooltips, and dropdowns.
These are especially suited to spatial procedures.
[Feature guide](https://frcdesign.org/feature-guide/)

The source is currently Astro/Starlight + MDX. Content is grouped under
`src/content/docs`; page names use lowercase hyphens with section index files.
Adjacent `img/` folders keep ordinary content images near their owners.
Authors explicitly register pages in `src/config/sidebarConfig.ts`.
Shared components normalize figures, slides, callouts, link buttons and image
tables. The source permits per-directory/per-page outline behavior.
[Adding a page](https://frcdesign.org/contribution/adding-a-page/)

Source configuration uses the Cloudflare adapter; CI builds and checks rendered
local links/assets. Contributor documentation also describes checking the shape
of Onshape workspace URLs. This is evidence of maintenance machinery, not proof
that every external document is available or correct.

## Maturity has limits

The user's longer-history observation is reasonable context, but this research
did not establish rigorous effectiveness testing or validate every UI decision.
The present source shows concrete drift:

- Educator Stage 1A still describes a four-exercise sequence centered on older
  Onshape courses; the current student sidebar has three sections and many more
  exercises.
- The Stage 1 educator overview describes A–D, while current student material
  includes 1E.
- The Stage 2D summary mentions a later Stage 3, while the current course
  navigation ends with Next Steps.

Use current learner pages and sidebar for sequence, and treat older educator
summaries cautiously. For Chiron, shared lesson IDs, a single course-order source,
and educator review during lesson changes would reduce this drift.

## Transfer to Chiron

Adopt separate course/reference entry points, illustrated outcomes, consistent
lesson structures, repeated practice, explicit self-review, and author guidance.
Use diagrams and notebook outputs where they explain programming behavior.
A CAD slideshow is useful inspiration, but not a requirement to build a custom
carousel. Good program traces and small runnable exercises may serve the same
teaching purpose with less maintenance.
